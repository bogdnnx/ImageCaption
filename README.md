# Image Captioning API

> Веб-сервис для автоматической генерации текстовых описаний к изображениям товаров
> на основе мультимодальных моделей Vision-Language, запускаемых локально через Ollama.

Сервис принимает изображение и пользовательский промт, ставит задачу генерации в очередь
и асинхронно обрабатывает её VLM-моделью через Ollama, не блокируя API. Результат
сохраняется в БД и доступен по идентификатору. Инференс выполняется локально — данные не
покидают контур. Подходит как основа для автонаполнения карточек товаров, генерации
alt-текста и подписей к медиабиблиотекам.

## Возможности

- **Локальный инференс.** Модели запускаются через Ollama на собственном сервере, без
  облачных API и передачи изображений вовне.
- **Асинхронная обработка.** Тяжёлый инференс вынесен в Celery-воркер — API мгновенно
  отвечает `202 Accepted` и не держит соединение на время генерации.
- **Кеширование по содержимому.** Повторная загрузка того же изображения с тем же промтом
  и моделью отдаёт готовое описание из БД, без повторного инференса (см. ниже).
- **Управляемая генерация.** Пользователь задаёт собственный промт и выбирает модель из
  числа установленных в Ollama.
- **JWT-аутентификация.** Регистрация, вход и доступ к ресурсам только их владельцу.
- **Веб-интерфейс.** React SPA: загрузка изображения, выбор модели, ввод промта и
  отображение результата.
- **Готов к контейнерам.** Полный стек поднимается одной командой через Docker Compose.
- **Наблюдаемость.** Мониторинг очереди и задач через Flower, интерактивная документация
  через Swagger UI.

## Архитектура

```text
   ┌──────────┐                         ┌──────────────┐
   │ React SPA│                         │  PostgreSQL  │
   └────┬─────┘                         └──────▲───────┘
        │ HTTP/JSON                            │ (SQLAlchemy 2.0, asyncpg)
        ▼      202 / poll                 ┌────┴─────┐   задача   ┌───────────┐
   ┌─────────────────────────────────────┤ FastAPI  ├──────────► │   Redis   │
   │                                      │  (async) │            │ (broker)  │
   │                                      └──────────┘            └─────┬─────┘
   │                                                                    │ FIFO
   │                                                              ┌─────▼──────┐
   │ файловое                                                     │   Celery   │
   └─ хранилище ◄───────────────────────────────────────────────│   Worker   │
                                                                  └─────┬──────┘
                                                                        │ HTTP
                                                                  ┌─────▼──────┐
                                                                  │   Ollama   │
                                                                  │ (VLM-модель)│
                                                                  └────────────┘
```

Путь запроса: клиент загружает изображение → FastAPI сохраняет файл и метаданные, ставит
задачу в Redis и сразу отвечает `202` → Celery-воркер забирает задачу, отправляет
изображение в Ollama на инференс → результат пишется в PostgreSQL → клиент забирает
готовое описание через polling.

## Быстрый старт

Требуется установленный Docker и Docker Compose.

```bash
# 1. Подготовить переменные окружения
cp .env.example .env        # при необходимости отредактировать .env

# 2. Поднять весь стек
docker compose up -d

# 3. Скачать VLM-модель в Ollama (один раз)
docker compose exec ollama ollama pull qwen2.5vl:3b

# 4. Проверить, что сервисы запустились
docker compose ps
```

После запуска доступны:

| Сервис            | URL                            |
| ----------------- | ------------------------------ |
| Веб-интерфейс / API | http://localhost:8000        |
| Swagger UI        | http://localhost:8000/docs     |
| Flower (Celery)   | http://localhost:5555          |

## Конфигурация

Все настройки задаются через переменные окружения в файле `.env`.

| Переменная       | Описание                                  | Пример                          |
| ---------------- | ----------------------------------------- | ------------------------------- |
| `DATABASE_URL`   | Строка подключения к PostgreSQL           | `postgresql+asyncpg://...`      |
| `REDIS_URL`      | Адрес брокера Redis                       | `redis://redis:6379/0`          |
| `OLLAMA_HOST`    | Адрес Ollama API                          | `http://ollama:11434`           |
| `SECRET_KEY`     | Ключ подписи JWT                          | `<случайная строка ≥ 32 симв.>` |
| `MODEL_NAME`     | Модель Ollama по умолчанию                | `qwen2.5vl:3b`                  |

## API

Базовый префикс — `/api`. Все эндпоинты, кроме регистрации и входа, требуют заголовок
`Authorization: Bearer <token>`.

### Аутентификация

| Метод  | Путь                  | Описание                       |
| ------ | --------------------- | ------------------------------ |
| `POST` | `/api/auth/register`  | Регистрация пользователя       |
| `POST` | `/api/auth/login`     | Вход, выдача JWT access-токена |

### Изображения

| Метод    | Путь                  | Описание                              |
| -------- | --------------------- | ------------------------------------- |
| `POST`   | `/api/images/upload`  | Загрузка изображения                  |
| `GET`    | `/api/images/`        | Список изображений пользователя       |
| `GET`    | `/api/images/{id}`    | Детали изображения с описаниями       |
| `DELETE` | `/api/images/{id}`    | Удаление изображения                  |

### Описания

| Метод  | Путь                          | Описание                                     |
| ------ | ----------------------------- | -------------------------------------------- |
| `POST` | `/api/images/{id}/caption`    | Запуск генерации описания (async, `202`)     |
| `GET`  | `/api/images/{id}/captions`   | Список описаний для изображения              |

Полная интерактивная спецификация — в Swagger UI по адресу `/docs`.

## Кеширование результатов

Инференс VLM на CPU занимает десятки секунд, поэтому повторная генерация для уже
обработанного изображения избыточна. Сервис кеширует результаты по содержимому файла.

При загрузке вычисляется `SHA-256` от байтов изображения и сохраняется вместе с
метаданными. На запрос генерации формируется составной ключ:

```text
cache_key = sha256( image_hash | normalized_prompt | model_name )
```

Если в БД уже есть завершённое описание с таким ключом — оно возвращается сразу, без
постановки задачи в очередь. Ключ составной намеренно: одно и то же изображение с разным
промтом или на разной модели даёт разные описания, и кеш не должен их смешивать.

> Кеш срабатывает на байт-идентичные файлы. Для пережатых или изменённых в размере копий
> хэш будет другим — это осознанный компромисс в пользу точности (исключает выдачу чужого
> описания для похожего, но другого товара).

## Локальная разработка

Запуск компонентов вручную, без Docker (для отладки). Ollama при этом должна быть
запущена отдельно и доступна по адресу из `OLLAMA_HOST`.

```bash
# Терминал 1 — API с автоперезагрузкой
uvicorn app.main:app --reload

# Терминал 2 — Celery-воркер
celery -A app.tasks.celery_app worker --loglevel=info --concurrency=1

# Терминал 3 — Flower (опционально)
celery -A app.tasks.celery_app flower
```

> **Примечание.** Воркер запускается с `--concurrency=1`: инференс модели монопольно
> использует ресурсы, и параллельная обработка нескольких задач лишь замедлит каждую.

## Модели

Сервис работает с любыми мультимодальными моделями, доступными в Ollama. По умолчанию
используется `qwen2.5vl:3b` — компактная модель с поддержкой русского языка, пригодная
для запуска на CPU.

```bash
# Установить модель
docker compose exec ollama ollama pull qwen2.5vl:3b

# Список установленных моделей
docker compose exec ollama ollama list
```

Сменить модель по умолчанию можно через `.env`:

```env
MODEL_NAME=qwen3-vl:4b-instruct
```

Более крупные модели (`qwen2.5vl:7b-q4_K_M`, `qwen3-vl:4b-instruct`,
`qwen3-vl:8b-instruct`) дают более качественные описания ценой большего времени генерации
и объёма памяти. Модель также можно выбрать на каждый запрос — через поле `model_name` в
теле запроса на генерацию или в веб-интерфейсе.
